# 构造体卡牌对战 MVP

桌面端优先的双人卡牌对战原型。玩家注册登录、浏览已发布卡牌、构筑并启用合法牌组，再通过六位房间码加入同一房间；服务端保存权威状态并过滤隐藏信息。管理员可以逐张录入完整卡图、规则文本和结构化效果。

## MySQL 初始化

项目使用本机 MySQL 8。复制环境变量模板并填写本地连接信息：

```powershell
cd D:\UnityProject\luxiya
Copy-Item .env.example .env
notepad .env
```

`.env` 已被 Git 忽略。服务启动和数据库命令会自动创建 `MYSQL_DATABASE` 指定的数据库及所需表。

首次初始化：

```powershell
npm.cmd run db:seed-cards -w @pgr/server
npm.cmd run db:bootstrap-admin -w @pgr/server
```

- `db:seed-cards` 幂等导入静态卡表，不覆盖管理员编辑。缺少完整卡图或结构化效果的卡牌保持草稿。
- `db:bootstrap-admin` 使用 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 创建或更新管理员。密码经 `scrypt` 哈希，明文不会写入数据库或日志。
- 初始化完成后应更换临时管理员密码；生产部署必须使用 HTTPS。

## 本地启动

```powershell
npm.cmd install
npm.cmd run dev
```

- Web：<http://localhost:5173>
- Server：<http://localhost:3001>
- 健康检查：<http://localhost:3001/api/health>

首次打开 Web 先注册或登录。玩家需要在“牌组编辑”中保存并启用一个合法牌组：恰好 50 张、同编号最多 4 张，红蓝黄信号球各 4 张。之后一个玩家创建房间，另一个输入房间码加入，双方点击“使用启用牌组准备”。

管理员使用 `Anonce` 登录后可看到“卡牌录入”。发布卡牌要求完整图片、规则文本、结构化效果配置，以及服务端已注册的复杂效果处理器。

## 工作区

- `packages/protocol`：共享协议与公开类型。
- `packages/cards`：示例卡牌注册表和 50 张开发牌组。
- `packages/game-core`：确定性规则状态机与玩家视图过滤。
- `apps/server`：MySQL 持久化、账号/卡牌/牌组/房间 HTTP API 与 Socket.IO 权威服务。
- `apps/web`：登录、卡库、牌组编辑、管理员录卡和 React 战术指挥台界面。

## 当前规则边界

首版已建模起手调度、阶段推进、费用、属性条件、出场、信号球、攻击、阻挡、响应、攻击充能、伤害充能、侵蚀、牌组更新、结束阶段和认输。卡牌效果同时保存玩家阅读文本与结构化配置；复杂效果通过稳定 `handlerId` 连接规则引擎。协战、浮空和未确认的综合规则不会被静默猜测，相关卡牌保持草稿。

多窗口开发前请先阅读并追加根目录 [`开发记录.md`](./开发记录.md)。

## 可视化效果录入

管理员在“卡牌录入”中可以直接编辑已有卡牌。效果编辑器按照“能力类型 → 触发 → 条件 → 代价 → 目标 → 动作 → 持续时间”组织，并提供常用模板、中文摘要、目标选择提示和高级 JSON 入口。一般录卡只需要使用可视化字段；高级 JSON 仅用于尚未做成表单控件的复杂规则。

日常录卡无需填写效果 ID 或目标 ID：系统自动生成内部编号，动作中的“作用对象”通过中文下拉菜单关联所选卡牌。支持筛选卡牌、按所选数量计算数值和编辑分支选项；处理器字段折叠在开发人员设置中。卡库、牌组卡池、录入表单和长规则详情各自滚动，可完整浏览卡图与规则。

已有卡牌可从录入页右上角“删除卡牌”删除。删除前会确认，删除资料与卡图后不可撤销；被牌组引用的卡牌会被拒绝删除，需要先从相关牌组移除。已经开始的对局继续使用其定义快照。

当前 `卡牌.md` 中的 20 张卡牌均已转换为可执行的结构化效果。上传完整卡图后即可按发布校验结果发布；服务端不会通过空处理器绕过未支持规则。玩家对局中的选牌、排序、追加弃牌等决策由服务端生成，客户端只提交合法选项。

## 隔离端到端测试

`npm.cmd run test:e2e` 使用 Web `5184`、Server `3011` 和固定随机种子启动隔离测试环境，仍连接 `.env` 配置的本地 MySQL。测试会验证管理员发布真实卡牌、两名玩家构筑并启用牌组、创建房间、攻击响应、结构化效果结算、隐藏信息、双端日志和 1920×1080 / 1280×720 布局。

尚未进入当前卡表的综合规则机制（例如协战、浮空及其未确认交互）仍保留为后续扩展点，不会被静默猜测或标记为已支持。

## 对局展示与操作

双方开局可同时进行调度，全部确认后才进入先攻回合。调度、费用填充、支付和效果选牌会自动弹窗；单张目标也可先查看效果再确认。战术牌及攻击/伤害充能牌会先公开放入处理区，由服务器展示约1.1秒后继续处理；需要选择的效果会保留卡牌，直到选择完成。断线期间暂停处理，重连后继续。这个停留仅用于展示，不限制玩家做选择的时间。

对局卡图从已上传的公开图片接口读取，缺失时回退占位卡面；对方手牌和暗费继续隐藏。抽牌、弃牌有可见反馈与动画，并遵从系统的减少动态效果设置。更新对局流程后建议刷新页面并重新创建房间。

端到端测试使用 `E2E-BP01-007` 等独立编号和可解码的测试卡图，不再上传或覆盖正式编号卡牌的图片。

## 角色出场与战斗选择

点击可使用的手牌后，从弹窗中选择通常使用、升变对象或装备对象。角色可选择任意合法空位；升变在符合条件的原角色位置进行，实际支付费用由服务端提供。选择方式与位置后，再选择要支付的费用牌并确认。

在线对局由服务器自动执行竖直和本回合抽牌，玩家只需在“抽牌完成”中确认，再进入费用填充；刷新和重连不会重复抽同一次牌。点击场上角色的“攻击”会先打开目标选择，允许攻击对方玩家或符合规则的横置角色。受攻击方自动收到阻挡询问，可选择合法角色、使用瞬时战术或不阻挡；关闭询问后可通过中央按钮重新打开。属性与卡牌类型均显示为中文。

5费《露西亚·红莲》的使用弹窗顶部提供独立的“通常出场 · 费用5”和“升变召唤 · 费用2”入口。升变要求费用区至少5张、战场有费用不超过5且具有〈露西亚〉特征的角色，并可合法支付2费；不满足时显示服务端给出的具体条件提示。只有一个升变对象时，点击升变入口会自动选中该对象，仍需选择费用并确认。

信号球按先进入的在前、后进入的在后显示；排列能力会自动弹出排序窗口，可拖动或使用“前移 / 后移”，再点击“确认顺序”。卡牌返回手牌后统一为正面竖直状态。暗费在双方战场和支付列表均显示背面，持有者点击仍可查看真实详情，对手无法查看。

装备有两种使用方式：点击手牌装备，在使用弹窗选择“装备 A…”，支付费用后直接装备；也可以先选择空位放到战场，在己方主要阶段点击该装备的“装备”，选择一名未持有装备的己方角色并确认，无需重复支付出场费用。已装备的卡牌显示在角色上方的装备标记中，点击标记可查看详情；每名角色最多持有一张装备。
